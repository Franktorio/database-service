# API Reference

Base URL (default): `http://localhost:8000` (configurable via `API_PORT`).

Interactive OpenAPI docs are auto-generated by FastAPI at **`/docs`** (Swagger UI) and **`/redoc`**. Authentication is now enforced via FastAPI `Depends()` dependencies (see [Engineering Report](ENGINEERING_REPORT.md#4-api-design)), so every protected route's `401`/`403`/`429`/`503` responses and required credential are declared as real parameters and appear in the generated schema. Treat this document as the source of truth for the exact auth requirements per route regardless.

## Authentication

The service supports **two independent auth schemes**. Every endpoint below states which one it uses.

### 1. API key (Bearer token)

Used for machine-to-machine / admin API calls.

```
Authorization: Bearer <raw_api_key_token>
```

- The raw token is only ever shown **once**, at creation time (`POST /api/db/keys`). The server stores only `sha256(API_KEY_PEPPER:token)` — it cannot be recovered if lost; a new key must be issued.
- Each key carries a `permission_level` (see table below) and a per-key `rate_limit` (requests per `RATE_LIMIT_WINDOW_SECONDS`, default 60s).
- Implemented as a chain of FastAPI dependencies in [`src/security/validation/api_security.py`](../src/security/validation/api_security.py): `get_current_api_key` (resolves + validates the key exists) → `api_key_rate_limited_factory()` (enforces the key's own rate limit) → `api_key_authorized_factory(permission_level)` (enforces the minimum permission level). Routes depend on `api_key_authorized_factory(...)` directly; there is no decorator anymore.

### 2. Cookie (JWT session)

Used for browser-style sessions. Obtained via `POST /login-auth-test` (see below) which sets an `httponly` cookie named `auth_token` containing a signed JWT.

- The JWT is stateless (`HS256`, `JWT_SECRET`) **and** tracked server-side in the `auth_cookies` table, so it can be revoked (e.g., on password change) even though the token itself hasn't expired.
- `secure` flag is automatically `true` when `OPERATING_MODE=production` (requires HTTPS).
- Implemented as a chain of FastAPI dependencies in [`src/security/validation/cookie_security.py`](../src/security/validation/cookie_security.py): `get_cookie_claims` (decodes/shape-validates the JWT) → `cookie_rate_limited_factory()` (enforces the per-token rate limit) → `get_current_cookie_data` (validates the DB-backed cookie row + resolves user permissions) → `cookie_authorized_factory(required_roles=...)` (optional role check). Routes depend on `cookie_authorized_factory(...)` directly; there is no decorator anymore.

> Both `POST /login-auth-test` and `POST /cookie-auth-test` are **test/utility routes** and are only mounted when `API_EXPOSE_TEST_ENDPOINTS=true` (default in development, default `false` otherwise). They exist to exercise the auth stack, not as the final login UX for a real application — see the [Expansion Guide](EXPANSION_GUIDE.md) for how to build real login endpoints on top of the same primitives.

## Permission levels

Defined in [`src/api/config.py`](../src/api/config.py):

| Level | Name | Typical use |
|:---:|---|---|
| `0` | `VIEW` | Read-only access |
| `1` | `EDIT` | Can modify existing resources |
| `2` | `BULK_OPERATIONS` | Can perform bulk/administrative writes |
| `3` | `ADMIN` | Administrative access |
| `4` | `SUPER_ADMIN` | Full system control — **cannot be created or granted via the API**; only via `python3 -m tools.scripts.generate_api_key 4 <rate_limit>` run directly on the host. |

All `/api/db/*` routes currently require `SUPER_ADMIN` (level `4`). This is intentionally the highest bar in the system — see the [Expansion Guide](EXPANSION_GUIDE.md) for how to use lower permission levels for new, non-system routes.

## Cross-cutting behavior (every route)

Every route below is protected, in this order, by:

1. **`@with_ip_block`** (still a decorator) — checks whether the caller's IP is currently blocked (Redis-tracked burst detection). If `IP_BLOCKING_ENABLED=true` and the IP has exceeded `IP_BLOCKING_THRESHOLD` requests within `IP_BLOCKING_TIME_WINDOW` seconds, the request is rejected with `429` for `IP_BLOCKING_DURATION` seconds — **before** authentication is even checked.
2. **Authentication + rate limiting** — a FastAPI `Depends(api_key_authorized_factory(...))` or `Depends(cookie_authorized_factory(...))` parameter on the route — validates the credential, then enforces the identity's own rate limit (distinct from the IP-block check above).

If Redis is unreachable, both layers **fail closed**: the request receives `503 Service Unavailable` rather than silently skipping the check.

## Root & diagnostic routes

### `GET /`

- **Auth:** none (but still passes through IP blocking)
- **Response `200`:**
  ```json
  { "message": "Hello from the backend!" }
  ```

### `POST /api-auth-test` *(test route — gated by `API_EXPOSE_TEST_ENDPOINTS`)*

- **Auth:** API key, `VIEW` level or above
- **Response `200`:**
  ```json
  { "message": "API key is valid: api_key_fingerprint=... permission_level=... permission_name=... rate_limit=..." }
  ```
- **Errors:** `401` missing/invalid key, `403` insufficient permission/unregistered key, `429` rate limited, `503` Redis unavailable — all as `{"detail": {"error": "...", "retry_after": ...}}`.

### `POST /login-auth-test` *(test route — gated by `API_EXPOSE_TEST_ENDPOINTS`)*

- **Auth:** none (this route *performs* authentication)
- **Body:**
  ```json
  { "username": "alice", "password": "hunter2" }
  ```
- **Behavior:** Verifies the password (rate-limited per-username via `LOGIN_ATTEMPTS_LIMIT`/`LOGIN_TIME_WINDOW`), then issues a JWT cookie valid for **10 minutes** (hardcoded test default) and returns:
  ```json
  { "message": "Login successful." }
  ```
  with `Set-Cookie: auth_token=...; HttpOnly; SameSite=Lax`.
- **Errors:** `401` invalid credentials, `429` rate limited, `503` Redis unavailable.

### `POST /cookie-auth-test` *(test route — gated by `API_EXPOSE_TEST_ENDPOINTS`)*

- **Auth:** Cookie (`auth_token`)
- **Response `200`:**
  ```json
  { "message": "Cookie authentication successful." }
  ```
- **Errors:** `401` missing/invalid/expired/revoked cookie, `429` rate limited, `503` Redis unavailable.

## API Key Administration — `/api/db/keys`

All routes require **`SUPER_ADMIN` (level 4)** API key auth. Source: [`src/api/system/api_db_endpoints/routes/`](../src/api/system/api_db_endpoints/routes/).

### `GET /api/db/keys`

List all API keys.

- **Response `200`:**
  ```json
  {
    "api_keys": [
      {
        "id": 1,
        "permission_level": 1,
        "rate_limit": 1000,
        "email": "svc-billing@example.com",
        "created_at": "2026-07-27T04:00:00Z",
        "last_updated_at": "2026-07-27T04:00:00Z",
        "permission_name": "EDIT"
      }
    ]
  }
  ```
  Returns `{"message": "No API keys found."}` if empty.

> **Note:** `id` is the API key's opaque public identifier, used as the path param for `PATCH`/`DELETE` below. The internal `key_hash` (SHA-256 digest of the key's secret token) is never returned by any endpoint — it exists purely as a server-side lookup value.

### `POST /api/db/keys`

Create a new API key.

- **Body** (`ApiKeyCreateRequest`):

  | Field | Type | Required | Notes |
  |---|---|:---:|---|
  | `permission_level` | int | no (default `0`) | `0`–`3` only — `4` (`SUPER_ADMIN`) is rejected with `403` |
  | `rate_limit` | int | no (default `1000`) | requests per `RATE_LIMIT_WINDOW_SECONDS`; must be `≥ 1` |
  | `email` | string | no | free-form label for the key owner |

- **Response `200`:**
  ```json
  {
    "message": "API key created successfully.",
    "api_key": {
      "id": 1,
      "token": "s3cr3t-raw-token-shown-only-now",
      "permission_level": 1,
      "permission_name": "EDIT",
      "rate_limit": 1000,
      "email": "svc-billing@example.com"
    }
  }
  ```
  **The `token` value is shown exactly once.** Store it immediately — only its hash is retained server-side. **Store `id` too** — it's the opaque identifier needed for later `PATCH`/`DELETE` calls.
- **Errors:** `403` if `permission_level >= 4`.

### `PATCH /api/db/keys/{key_id}`

Partially update permission level, rate limit, and/or email.

- **Path param:** `key_id` — the opaque integer `id` obtained from `GET /api/db/keys` or the `POST /api/db/keys` create response.
- **Body** (`ApiKeyPatchRequest`, all fields optional):

  | Field | Type | Notes |
  |---|---|---|
  | `new_permission_level` | int \| null | `0`–`3`; `4` rejected with `403` |
  | `new_rate_limit` | int \| null | `≥ 1` |
  | `new_email` | string \| null | |

- **Response `200`:** updated key object (same shape as list entry, plus `permission_name`).
- **Errors:** `403` if promoting to `SUPER_ADMIN`; `404` if `key_id` doesn't exist.

### `DELETE /api/db/keys/{key_id}`

- **Response `200`:** `{"message": "API key deleted successfully."}`
- **Errors:** `404` if not found.

## User Administration — `/api/db/users`

All routes require **`SUPER_ADMIN` (level 4)** API key auth. Source: [`src/api/system/user_db_endpoints/routes/`](../src/api/system/user_db_endpoints/routes/). Roles are stored in normalized `roles`/`user_roles` tables (see [DATABASE.md](DATABASE.md#roles--user_roles)), not on the user row itself — `roles`/`role` below are resolved on read, and `role` is always the oldest-granted (first) role.

### `GET /api/db/users`

List all users (passwords/salts are never included in the response).

- **Response `200`:**
  ```json
  {
    "users": [
      {
        "id": 1,
        "username": "alice",
        "email": "alice@example.com",
        "roles": ["admin"],
        "role": "admin",
        "login_rate_limit": 10,
        "hash_algorithm": "pbkdf2_sha256",
        "hash_iterations": 210000,
        "created_at": "2026-07-27T04:00:00Z",
        "last_updated_at": "2026-07-27T04:00:00Z"
      }
    ]
  }
  ```
  Returns `{"message": "No users found."}` if empty.

### `GET /api/db/users/{username}`

- **Response `200`:** `{ "user": { ...same shape as above... } }`
- **Errors:** `404` if the username doesn't exist.

### `POST /api/db/users`

Create a new user.

- **Body** (`UserCreateRequest`):

  | Field | Type | Required | Notes |
  |---|---|:---:|---|
  | `username` | string | **yes** | must be unique |
  | `password` | string | **yes** | hashed server-side with PBKDF2-HMAC-SHA256 (210k iterations by default) + per-user salt + global pepper |
  | `initial_role` | string | **yes** | normalized to lowercase; becomes the first entry in `roles` |
  | `email` | string | no | default `""` |
  | `login_rate_limit` | int | no (default `10`) | max login attempts per `LOGIN_TIME_WINDOW` |

- **Response `200`:** created user object (no password fields).
- **Errors:** `409` if `username` already exists.

### `PATCH /api/db/users/{username}`

Update email and/or roles. **Any role change or email change revokes all of the user's existing auth cookies** (forces re-login), matching the CRUD implementation.

- **Body** (`UserUpdateRequest`, all optional):

  | Field | Type | Notes |
  |---|---|---|
  | `new_email` | string \| null | |
  | `set_roles` | string[] \| null | full replacement of the role list; must be non-empty, normalized/deduplicated |
  | `add_role` | string \| null | appended if not already present |
  | `remove_role` | string \| null | rejected with `400` if it's the user's only remaining role |

- **Response `200`:** updated user object.
- **Errors:** `400` invalid role operation (e.g., removing the last role, empty role string); `404` user not found.

### `PATCH /api/db/users/{username}/password`

Rotate a user's password. **Revokes all existing auth cookies for the user** (forces re-login everywhere).

- **Body** (`UserPasswordUpdateRequest`): `{"new_password": "..."}`
- **Response `200`:** `{"message": "User password updated successfully.", "user": {...}}`
- **Errors:** `404` user not found.

### `PATCH /api/db/users/{username}/login-rate-limit`

- **Body** (`UserLoginRateLimitUpdateRequest`): `{"new_login_rate_limit": 15}` (must be `≥ 1`)
- **Response `200`:** `{"message": "User login rate limit updated successfully.", "user": {...}}`
- **Errors:** `404` user not found.

### `DELETE /api/db/users/{username}`

Deletes the user and cascades to all of their auth cookies.

- **Response `200`:** `{"message": "User '{username}' deleted successfully."}`
- **Errors:** `404` user not found.

## Role Administration — `/api/db/roles`

All routes require **`SUPER_ADMIN` (level 4)** API key auth. Source: [`src/api/system/roles_db_endpoints/routes/`](../src/api/system/roles_db_endpoints/routes/).

### `GET /api/db/roles`

List all defined roles.

- **Response `200`:**
  ```json
  {
    "roles": [
      {
        "id": 1,
        "name": "admin",
        "description": "Administrative role",
        "created_at": "2026-07-27T04:00:00Z",
        "last_updated_at": "2026-07-27T04:00:00Z"
      }
    ]
  }
  ```
  Returns `{"message": "No roles found."}` if empty.

### `GET /api/db/roles/{role_id}`

- **Response `200`:** `{ "role": { ...same shape as list entry... } }`
- **Errors:** `404` if `role_id` doesn't exist.

### `POST /api/db/roles`

Create a new role.

- **Body** (`RoleCreateRequest`):

  | Field | Type | Required | Notes |
  |---|---|:---:|---|
  | `name` | string | **yes** | normalized to lowercase; must be unique |
  | `description` | string | no | default `""` |

- **Response `200`:** created role object.
- **Errors:** `409` if a role with the same normalized name already exists.

### `PUT /api/db/roles/{role_id}`

Update a role's name and/or description.

- **Body** (`RoleUpdateRequest`, all fields optional but at least one required):

  | Field | Type | Notes |
  |---|---|---|
  | `new_name` | string \| null | normalized to lowercase; must remain unique |
  | `new_description` | string \| null | |

- **Response `200`:** updated role object.
- **Errors:** `400` if no update fields are provided; `404` role not found; `409` name conflict.

### `DELETE /api/db/roles/{role_id}`

- **Response `200`:** `{"message": "Role '{role_id}' deleted successfully."}`
- **Errors:** `404` if role not found; `409` if the role is still assigned to one or more users.

## Audit Log Administration — `/api/db/audit-logs`

All routes require **`SUPER_ADMIN` (level 4)** API key auth. Source: [`src/api/system/audit_log_endpoints/routes/`](../src/api/system/audit_log_endpoints/routes/). **Read-only:** there is no create/update/delete route — entries are written automatically by the CRUD layer (see [`DATABASE.md`](DATABASE.md#audit_logs)) whenever a `users`, `roles`, or `api_keys` row is created, updated, or deleted; they cannot be written, edited, or removed via the API.

### `GET /api/db/audit-logs`

List audit log entries, most recent first.

- **Query params:**

  | Field | Type | Default | Notes |
  |---|---|---|---|
  | `limit` | int | `100` | `1`–`500` |
  | `offset` | int | `0` | `≥ 0` |

- **Response `200`:**
  ```json
  {
    "audit_logs": [
      {
        "id": 1,
        "action": "api_key.create",
        "user_id": null,
        "api_key_id": 3,
        "ip_address": "127.0.0.1",
        "timestamp": "2026-07-27T04:00:00Z"
      }
    ]
  }
  ```
  Returns `{"message": "No audit logs found."}` if empty.
- `user_id`/`api_key_id` identify **who performed the action** (whichever credential type authenticated the request), not the resource that was changed — see `action` for what happened. Exactly one of them is typically non-null, since today every `system` admin route is `SUPER_ADMIN` API-key-gated.

### `GET /api/db/audit-logs/{log_id}`

- **Response `200`:** `{ "audit_log": { ...same shape as a list entry... } }`
- **Errors:** `404` if `log_id` doesn't exist.

---

> **Standardized error envelope:** every error response raised by this API uses `detail: {"error": "<message>", "retry_after": <seconds-or-null>}` — see [`src/api/errors.py`](../src/api/errors.py)'s `api_error()` helper, used by every route and security dependency instead of raw `HTTPException(...)`. A single client-side handler can always read `response.json()["detail"]["error"]` and optionally `["retry_after"]` (non-`null` only for `429`s), regardless of which layer raised the exception.

> **Typed responses:** every route below declares a `response_model=` (see each endpoint folder's `models.py`, e.g. [`api_db_endpoints/models.py`](../src/api/system/api_db_endpoints/models.py), [`user_db_endpoints/models.py`](../src/api/system/user_db_endpoints/models.py), [`roles_db_endpoints/models.py`](../src/api/system/roles_db_endpoints/models.py)), so response shapes are validated by FastAPI/Pydantic and documented in the OpenAPI schema — not just hand-built dicts.

## Error reference

| Status | Meaning | Where it comes from |
|:---:|---|---|
| `400` | Invalid request body/state (e.g., invalid role operation) | Route-level validation, `ValueError` → `HTTPException` |
| `401` | Missing/invalid API key or cookie token; wrong/expired credential | `api_key_authorized_factory`/`get_current_api_key`, `cookie_authorized_factory`/`get_current_cookie_data`, `authenticate_password` |
| `403` | Authenticated but insufficient permission level, or attempted `SUPER_ADMIN` creation via API | `api_key_authorized_factory`, `cookie_authorized_factory`, key/user admin routes |
| `404` | Resource not found (user, role, API key) | Route handlers |
| `409` | Conflict (e.g., username already exists, role name already exists, or deleting an in-use role) | `POST /api/db/users`, role admin routes |
| `429` | Rate limit exceeded (per-identity) or IP temporarily blocked (burst detection) | `with_ip_block`, `api_key_authorized_factory`, `cookie_authorized_factory`, `authenticate_password` |
| `503` | Redis unavailable — auth/rate-limit/permission cache could not be evaluated | Any route wrapped by `with_ip_block` or gated by the auth dependencies |

> Every error `detail` is a `{"error": "...", "retry_after": ...}` object (see the standardized error envelope note above) — `retry_after` is `null` except on `429` responses.
